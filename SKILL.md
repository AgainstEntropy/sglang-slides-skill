# sglang-slides — building RadixArk house-style pptx decks

Generate RadixArk / SGLang style talk decks in Python. **Do not use pptxgenjs / node**,
and do not hand-write from blank python-pptx — this skill's `sgl_deck.py` already
packages the design system into helpers.

## Workflow

1. **Read [`design-system.md`](design-system.md) first**: tokens, the 9 layout patterns, QA process.
   Worked examples: `examples/example-deck.pptx` (one slide per pattern, generated by
   `examples/make_example.py` — read that script when you want the code for a given pattern).
2. **Write a build script** (one script per deck, kept in the talk's own directory). Skeleton:

   ```python
   # /// script
   # requires-python = ">=3.10"
   # dependencies = ["python-pptx>=1.0", "qrcode[pil]"]
   # ///
   import sys
   from pathlib import Path
   sys.path.insert(0, str(Path("~/.claude/skills/sglang-slides").expanduser()))
   from sgl_deck import Deck, ACC, ACC2, INK, SUB, MUT, LINE, PANEL, TINT, TINT2, MX, CW, W

   d = Deck(author="…", title="…")
   s = d.slide()                # white background + automatic page number (none on the title slide)
   d.eyebrow(s, "SECTION")      # small all-caps label, top left
   d.title(s, "Slide title")
   d.lead_bullets(s, [("Bold lead — ", "gray explanation"), …], x=MX, y=1.6, w=6.4, h=4)
   d.save("out.pptx")
   ```

   Run it with `uv run build.py` (uv builds the environment from the PEP 723 header; nothing needs
   to be pre-installed on the machine).
3. **QA** (design-system.md §5): validator (when available) → full-text check with `markitdown` →
   if a renderer is available, look at every page as an image (text overflow is the most common defect).
4. Real-world reference: the build script for a complete 14-slide talk lives at
   `../sglang-diffusion/talks/amazon/pptx-src/build.py`.

## API cheat sheet (see the `sgl_deck.py` docstrings for details)

| Need | Call |
|---|---|
| New slide (white + page number) | `s = d.slide()` |
| Eyebrow / title | `d.eyebrow(s, "FEATURES")` / `d.title(s, "…")` |
| Row of big numbers | `d.stat_row(s, [("37", "pipelines"), …], y=1.4)` |
| Term–explanation list | `d.lead_bullets(s, [(lead, rest), …], x, y, w, h)` |
| Plain bullets | `d.bullets(s, ["…", …], x, y, w, h)` |
| Mixed rich text | `d.rich(s, [(txt, {"bold":1,"color":ACC,"br":1}), …], x, y, w, h)` |
| Card / panel | `d.card(s, x, y, w, h, fill=PANEL, line=LINE, dash=False)` |
| Diagram box / arrow / triangle / ellipse | `d.box` / `d.arrow` / `d.tri` / `d.ellipse` / `d.line` |
| Table (no blue banded style) | `d.table(s, rows, x, y, col_w=[…], row_h=0.6)`; a cell may be `(text, {"bold","color","fill","align"})` |
| Code block | **carbon image**: `uv run scripts/carbonize.py <snippet> <out.png>` → `d.image(s, png, x, y, w=…)` (height follows width automatically); offline fallback `d.code_panel()` |
| Image / logo | `d.image(s, ASSETS/"sglang-logo.png", x, y, w=…)` |
| QR code (generated on the spot) | `d.qr(s, url, x, y, w, caption="…")` |

## Hard rules

- Fonts: **Calibri** only (Courier New for code) — safe-list, so QA matches what a real machine renders.
- Colors: only the tokens in design-system.md §2; **ACC at most 3 places per slide**.
- Never write a number you have not measured; use italic MUT or an empty dashed card (`dash=True`) as
  a placeholder so "not filled in yet" is visible.
- Avoid: gradients / shadows / icon libraries / decorative color bars / underlined titles / a slide full of text.
- One punchline per slide (bold ACC on its own line), one main pattern per slide.

## Assets

`assets/`: `sglang-logo.png` (wide), `sglang-logo-square.png`, `sgl-diffusion-logo.png`.
Standalone QR image: `uv run scripts/make_qr.py <url> <out.png>`; code card:
`uv run scripts/carbonize.py <snippet> <out.png>` (needs node).
Add new assets (a Miles logo, product screenshots, …) straight into `assets/` and register them in
design-system.md §6.
